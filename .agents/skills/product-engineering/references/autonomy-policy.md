# 自主决策与授权

## 四级决策

| 级别 | 判定 | 行为 |
|---|---|---|
| A 自动推断 | 答案在仓库、配置、代码或官方资料中 | 读取证据后继续，不让用户代替调查 |
| B 自动验证 | 可用已授权且风险受控的测试/工具回答 | 实际验证并记录结果，不问“是否已修好” |
| C 可逆选择 | 低风险、有多个合理方案且在范围内 | 选最符合项目现状的方案，记录原因和回退办法 |
| D 用户确认 | 关键业务语义、重大范围/权限/数据改变，不可逆操作，生产/发布、安全/合规/显著费用/外部承诺风险 | 先调查，再在动作前取得具体授权 |

可逆不等于已授权：安装工具、覆盖配置、变更其他项目和外部写操作不能仅因可回退就自动执行。本 Skill 不执行自动安装/升级、部署、Issue/PR 创建；若完成依赖这些动作，交付明确的人工维护事项。

## 假设与事实

### HUMAN_GATE：业务含义优先

谁可以删除、可删除哪些对象/范围、软删除还是硬删除、数据保留、可恢复性、关联数据处理、权限边界、审计要求及删除后状态，均属于关键业务决策，而非默认的 C 类技术选择。

当项目现有规则不能确定、用户未明确且实施会产生实际业务行为时：必须标记相关语义 UNKNOWN、原任务 BLOCKED，进入 HUMAN_GATE。未确认前不得实施该行为，也不得编写将猜测固化为正确答案的业务测试。纯函数、数组过滤、本地代码、技术可逆均不能豁免；不存在的上层权限/审计机制不能作为已满足要求的假设。

确认针对尚缺的具体语义，不重复询问已有明确答案。业务确认通过也不代替 Spec Kit 或其他 Risk Gate。

使用 [decision-record](../templates/decision-record.md) 记录 C 类选择、采用的推断及被接受的风险。标注来源与置信边界，不把推断写成用户批准。需要影响正式规格时，经当前已授权的官方规格流程纳入，而不是在 Brief 中另立规则。

已有事实与目标要求不同，并不表示用户目标无效。先描述当前行为，再实现明确授权的目标；真正无法推断的业务冲突再询问。

## UNKNOWN 与暂停

UNKNOWN 表示证据不足，不等于失败、不存在或许可。记录未知项、已尝试调查、影响的阶段、可安全继续的工作与解除条件。

凡 UNKNOWN 阻止原目标实施或验收，按 TASK_BINDING 将原任务置为 BLOCKED。保持原目标与证据绑定：例如配置来源/约束无法确认，就报告该配置任务受阻，不改为修复 README 中另一个 Bug。

额外发现只记录或做安全只读调查，不自动扩大修复范围。只有另有明确修复授权且其独立路线/风险门允许时，才能用独立 Task Identity 修复；必须标注“这是额外发现，不是原任务的完成”。原任务仍 BLOCKED，不复用额外修复的测试/验收结果证明原目标达成。原任务 Spec Kit 门受阻时，不把独立修复当作继续原实施的通道。

区分两种暂停：

- 技术阻塞：缺少官方 Skill、目标路径异常、未知 schema、未知强制 hook、无法确认副作用、并行写冲突。停止依赖该能力的写操作，继续安全检查；不要求用户猜技术答案。
- 决策阻塞：安全检查后仍有 D 类选择，或官方流程要求而尚未获得的人工批准。请求用户确认。

没有官方能力不能用自制实现“绕过阻塞”。已有明确授权不重复询问；但不能将宽泛的“继续”解释为覆盖数据、生产操作或所有后续风险的许可。

## 确认请求格式

一次聚焦一个实际决策，提供：

1. 已确认事实与证据；
2. 当前不确定性；
3. 推荐方案及理由；
4. 其他可行方案；
5. 每个方案对数据、权限、用户体验、审计、实现成本和回滚的影响；
6. 不回答时的安全行为：保留现场，停止相应动作，不假设批准。

删除场景不能只问“软删除还是硬删除”。先引用调查证据说明哪些删除/恢复/管理员规则未发现，再列出剩余疑问；可建议明确授权角色的可恢复软删除并说明原因，同时给出硬删除等可行备选及各项影响。推荐不是批准，不预设所有项目都应软删除；无答复时不实施删除行为。

官方 Skill 的人工 gate/确认要求必须尊重；不能替用户点击批准，也不能修改其正文去掉确认。若官方规则导致暂停，指出具体来源和触发条件。分析阶段的“可提出修复建议”不等于已获实施批准。

## 重试与不可逆操作

重试前核验现场：是否已写文件、已执行迁移或发送请求；是否可安全重复。未知结果先查证，不重发有副作用动作。

连续两次同类失败且没有新增证据或可行方案时停止自动重试，报告当前状态和下一步；不是把技术失败转成业务提问。失败不允许清空用户变更、重建任务历史或降低验收条件。

测试也需风险检查：连生产库、清理真实数据、计费 API、自动发布的脚本不是普通安全测试。优先已有隔离测试配置；不存在则标记 BLOCKED，不擅自创建生产副作用。
